# 效果检查与维护

## 先核对事实，再检查表达

- 对象、条件、数值、引用归属、研究状态和判断力度是否保留？
- 去掉“针对、为此、从而”等连接词后，相邻句是否仍有明确的对象与关系？
- 解释是否帮助读者理解操作的必要性、产物或含义，而非增加无事实依据的机理？
- 论文、科研项目书、学术报告与用户要求的改写幅度是否匹配？
- 换研究主题后，是否仍保持表达方式而没有搬入示例中的研究内容？

## 有用的回归任务

1. 无性能结果的方法段：给定表示、约束、求解和恢复关系，检查是否形成连续对象而不编造高精度结论。
2. 学术进展：给出已观察差异、尚未控制条件与下一步比较，检查观察和归因是否区分。
3. 科研项目：给出已有基础、新增条件和拟研究内容，检查计划没有被写成成果。
4. 轻润色：保留引文、弱结论与原结构；成熟短段允许少改。
5. 压缩多算例：合并共性，保留差异、必要条件与比较目的。
6. 跨学科：使用材料或实验类主题，检查没有带入核工程或神经网络术语。

两个版本比较时使用同事实、同用途的材料，并查看具体句间关系。不要用连接词数量、自评分数或字数增加作为风格效果证据。

## 验证边界

初版构建时做过有限的独立方法段与进展报告试写，用于发现事实漂移和模板化；这些检查不是作者盲评。公开示例为构造展示，不是实际论文结果，也不代表其他使用者已经认可。

仓库提供的结构检查验证文件布局、内部链接与发布内容边界，不判断是否能模仿到某位作者，也不核验科研结论。后续应根据真实使用反馈改进具体规则，避免不断增加每段必须执行的步骤。
